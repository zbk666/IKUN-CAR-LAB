# CAR LAB v1.1：自定义环、蓝牙与曲线游标

## 1. 自定义 PID 环

进入“自定义环”页面后，可以直接配置：

- 目标命令 key
- Target 遥测 key
- Feedback 遥测 key
- Error 遥测 key（可留空，软件用 Target-Feedback）
- Output 遥测 key
- Kp/Ki/Kd 参数 key
- 单位

配置完成点击“应用当前映射”。之后目标值通过 CMD 发送，Kp/Ki/Kd 通过 SET 在线修改，MCU 用 ACK 回读确认。

也可以点击“保存为本地自定义环”，映射会保存在 `data/custom_loops.json`，下次启动仍可使用。

### MCU 例子

```json
{"type":"TEL","data":{"position_target":100,"position":92.5,"position_error":7.5,"position_output":36.2}}
```

YAML 对应：

```yaml
pid_loops:
  - key: position
    name: 位置环
    unit: mm
    target_command_key: position_target_cmd
    target_key: position_target
    feedback_key: position
    error_key: position_error
    output_key: position_output
    params: {Kp: position_kp, Ki: position_ki, Kd: position_kd}
```

MSP 模板新增 `car_lab_send_custom_loop(...)`，可用于单独发送一个自定义环的四个实时量。

## 2. 蓝牙串口

如果使用 HC-05/HC-06 或其他能在 Windows 中生成 COM 口的蓝牙串口模块：

1. 先在 Windows 蓝牙设置里完成配对。
2. 查看 Windows 分配的 COM 口。
3. CAR LAB 主界面连接方式选择“蓝牙串口”。
4. 填写 COM 口和波特率。
5. 点击连接。

对 MCU 来说它仍然是 UART，因此原来的 TEL/CMD/SET/GET/ACK 程序不需要改变。

## 3. BLE GATT

v1.1 增加 BLE GATT Transport，Python 依赖为 `bleak`。

主界面选择“BLE”后：

1. 点击“扫描 BLE”。
2. 选择设备。
3. 填写 Write UUID（PC -> MCU）。
4. 填写 Notify UUID（MCU -> PC）。
5. 可开启断线自动重连。
6. 点击确定连接。

BLE 接收到的 Notify 字节会继续交给 CAR LAB 的 JSON Lines 协议解析器，因此一条 JSON 消息即使被拆成多个 BLE 包也可以重新拼接。

> BLE 更适合参数、状态和中低速遥测。大量通道/高频波形仍优先 USB 串口、TCP 或后续 CAN。

### MCU/BLE 模块要求

- PC 写入 Write Characteristic 后，把收到的每个字节送入 `car_lab_rx_byte()`。
- `car_lab_uart_write()` 在 BLE 模式下可改为发送 Notify。
- 上层 TEL/CMD/SET/GET/ACK 逻辑不用变。

## 4. 曲线数据探针与 A/B 游标

示波器、Speed Lab、Heading Lab、自定义环现在支持：

- 鼠标悬停：吸附最近采样点并显示该时刻的数据。
- 十字游标：快速对准时间与数值。
- 第一次左键：锁定 A。
- 第二次左键：锁定 B。
- 自动计算 `Δt` 和各通道 `Δ值`。
- 第三次左键：重新开始 A/B 测量。

这适合测上升时间、振荡周期、响应延迟，并配合参数修改事件标记观察 PID 改动前后的差异。

## 5. 推荐使用顺序

速度环仍然优先使用 Speed Lab，快速看 Target/Actual 拟合；航向控制优先使用 Heading Lab，把角度外环和角速度内环分开分析；其他位置环、电流环、循迹环、平衡环等放在“自定义环”。


## 6. 无线调车安全

BLE/蓝牙断线时，上位机可能来不及发送“停止”命令，因此 MCU 必须自己实现通信看门狗。建议 200~500 ms 内没有收到有效控制/心跳就进入安全状态，并限制最大 PWM/转向输出。无线链路不能代替物理急停。
